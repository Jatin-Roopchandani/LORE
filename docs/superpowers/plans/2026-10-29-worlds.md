## Task 1: data, CLI and defaults (foundation)

- **Migration:**
  - add `worlds(id, name UNIQUE, created_at)` and `books.world_id`;
  - backfill one world per distinct series name and one per book with no series, named after the book;
  - make `world_id` required for new books.
- **`lore/worlds.py`:**
  - `list_worlds`, `get_world`, `create_world`, `rename_world`, `delete_world` (refuses if not empty);
  - `world_of(book)`, `books_in(world)`, `assign(book, world)` (row only);
  - `suggest_world(conn, series, title) -> (world_id | None, suggested_name)`, per spec §5.
- **CLI:**
  - `lore world list|rename|delete`;
  - `lore ingest --world NAME [--yes]`: creates the world after confirmation; with no `--world`, offers the suggestion;
  - `lore books` shows each book's world.
- **Tests:** backfill, suggestion order, the CLI prompts, and that a non-empty world can't be deleted.

## Task 2: resolution scoped to a world (needs 1)

- In the loader's cross-book steps, only entities whose `books` are all in the loading book's world are candidates. That covers homonym fusion, cross-book variants and alias-node redirects.
- Add an invariant check plus a test: after a load, every entity's books share one world.
- **Tests:** synthetic two-world graphs.
  - Same-named distinctive characters across worlds stay separate.
  - Within one world they merge, as today.
  - Re-loading is idempotent.

## Task 3: remove from graph, and move (needs 2)

- **`remove_book_from_graph(conn, kuzu, lance, book_id)`:**
  - deletes the book's chunks and their MENTIONS;
  - deletes its REL edges;
  - removes the book from each entity's `books`, deleting the entity when none remain;
  - deletes alias nodes and ALIAS_OF edges left with no books;
  - deletes its Lance chunk vectors and its beats (rows and vectors).

  It is idempotent.
- **Move job:** stages remove, reassign, load and beats through `run_book`. Stage names go into `pipeline.STAGES` or a move-specific stage list; keep the job row semantics consistent.
- **CLI:** `lore book move <book> --world NAME [--yes]` and `lore book remove-from-graph <book>`.
- **Round-trip test:** load books into a world, move one to another world and back. The full graph (entities, edges, books per entity, aliases) must equal the original, and the fake Gemini must record zero requests.

## Task 4: queries and graph API scoped to a world (needs 1; parallel with 2)

- `answer_question`, `lore_search` (MCP) and the web ask endpoint take an optional `world` (id or name).
  - Seeds, select candidates, graph evidence, vector and keyword candidates, the timeline and the decomposition's book list are all filtered to the world's books.
  - The default world follows spec §7.
- **"All worlds":** search each world and pool the evidence. Entities never merge across worlds. The answer names the world (or book) when facts come from more than one world.
- **Graph endpoints:** overview, subgraph, entity and expand take `world`. With "all", they return per-world clusters with a `world` field on each node.
- `GET /api/worlds` lists worlds with their books.
- **Tests:**
  - world A never returns world B's passages, entities or beats;
  - all-worlds keeps same-named entities distinct;
  - API shapes are correct.

## Task 5: UI (needs 3 and 4)

- **Header:** a world selector replaces the books dropdown. It lists each world plus "All worlds", and the choice is remembered in localStorage.
- **Graph pane:** follows the world. In all-worlds mode, colour or label nodes by world and show a legend.
- **History:** each item records its world; replaying it switches world.
- **Library panel:**
  - group books by world, with the series shown under each;
  - add "Move to world…" (pick or create, confirm, then run the job with the existing progress and Continue UI);
  - rename a world;
  - delete an empty world.
- **Add book dialog:** a World dropdown with the suggested default. The generated CLI command includes `--world`.
- All strings go in `messages.ts`.
- **Vitest coverage:** the selector, graph refetch on switch, Move, and the Add book default.
